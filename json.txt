JSON (JavaScript Object Notation) — текстовый формат обмена данными,
основанный на JavaScript. Но это и есть такой универсальный цифровой
бланк для передачи данных между мобильным приложением и сервером. Это
текстовый формат, который одинаково легко читают и люди, и компьютеры.

может использоваться в любом
языке программирования.

Зачем он нужен в Android? Приложение почти никогда не хранит все
данные внутри себя. Оно обращается к интернету (API), запрашивает
информацию (погоду, ленту новостей, список товаров), получает её в
формате JSON и показывает пользователю.

Внутри JSON всего два главных контейнера:
1. Объект {} (Object). Неупорядоченный набор пар «ключ-значение».
Ключ всегда в двойных кавычках, за ним двоеточие, потом значение.
Пары разделяются запятыми. Пример: { &quot;имя&quot;: &quot;Алексей&quot;, &quot;возраст&quot;: 19
}
2. Массив [] (Array). Упорядоченный список значений. Значения просто
перечисляются через запятую. Пример: [ &quot;Понедельник&quot;, &quot;Вторник&quot;,
&quot;Среда&quot; ]

Основные типы значений:
 Строка (&quot;Android&quot;).
 Число (4.0, 2026) - (целое или вещественное).
 Логическое значение (true или false).
 JSON-Объект ({ ... }).
 Массив ([ ... ]).
 Null (null — пустота).

Для студентов важно понимать не только код, но и путь данных. В типичном
приложении этот процесс выглядит так:
1. UI-слой (Activity/Fragment): Пользователь нажимает кнопку
«Загрузить профиль».
2. ViewModel: Прослойка говорит репозиторию: «Мне нужны данные
пользователя».
3. Репозиторий: Отвечает за источник данных. Он решает: взять их из
локальной базы (Room) или пойти в сеть.
4. Сетевой слой: Если данных нет, используется библиотека (например,
Retrofit или Volley). Она отправляет HTTP-запрос на сервер.
5. Сервер: Возвращает ответ в виде текста (строки) в формате JSON.
6. Парсинг: Сетевой слой превращает эту строку в понятные Kotlin-
объекты (модели).
7. Отображение: ViewModel передает готовые объекты в UI-слой, где
они привязываются к кнопкам, текстам и картинкам.

Способ 1. Ручной парсинг (на примере JSONObject)
Устаревший вариант: Библиотеки уже встроены в Android SDK, ничего
дополнительно скачивать не нужно. Подходит для очень маленьких ответов
от сервера.
Местонахождение: классы JSONObject и JSONArray (пакет org.json).
Плюсы: Не требует сторонних библиотек, полный контроль над каждой
строкой.
Минусы: Очень много рутины, риск опечататься в названии ключа, нулл-
безопасность полностью на плечах разработчика.

Способ 2. Автоматический (современный стандарт)
Вы описываете структуру данных в виде обычного класса (его называют
DTO — Data Transfer Object, или модель), а специальная библиотека сама
превращает JSON в этот класс.
Главная библиотека: Gson (от Google) или Moshi. Для простоты рассмотрим
Gson.
Для работы с форматом JSON существует библиотека от корпорации
Google – Gson. Библиотека позволяет осуществлять перевод из формата Json
в формат object и наоборот. Для использования библиотеки необходимо
добавить в скрипт buil.gradle (Module) в директиву dependencies следующую
строку:
mentation &#39;com.google.code.gson:gson:2.8.5&#39;
после чего запустить синхронизацию gradle. (Sync Project with Grable
Files)

После этих действий станет доступен статический класс Gson
Для перевода строки формата Json в формат object необходимо создать
объект, который будет соответствовать данным Json.

Также можно десериализовать объект в формат json.
Для этого необходимо использовать метод toJson() в который
необходимо передать объект или список объектов.

Шаг 1. Создание модели. Вы создаете обычный класс (лучше data class), где
имена полей совпадают с ключами в JSON.
Шаг 2. Библиотеки.
// Добавляем зависимость в build.gradle:
implementation &#39;com.google.code.gson:gson:2.10.1&#39;
Библиотека сама пробежится по всем полям, найдет нужные ключи,
преобразует строки в числа, создаст списки объектов Subject и аккуратно
положит null в поле middleName.
